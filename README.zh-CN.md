## 这是什么

调用闭源大模型 API 时，用户看不到服务端背后到底跑了什么：高峰期有没有偷偷路由到便宜的小模型？宣传的 `bf16` 权重有没有被压成 `int4`？有没有跳过中间几层、截断历史上下文，或者暗中改短隐藏的系统提示词来省推理步数？光看返回的文字，这些问题在低比例掺假时几乎无法察觉。

**FlashProve-Next** 让模型服务商可以给每一条 API 回复附上一份公开可验证的零知识证明，向任何人证实“这条回复确实出自官方公布的那套真实模型配置”，同时守住两条线上生产底线：

1. **完全不改动、不拖慢现有推理系统**：不需要像早期方案那样把模型转成专门的“定点整数替身”，也不限制解码方式。线上引擎照常运行原生浮点（`bf16`/`fp8`）、温度与 top-$p$ 随机采样、FlashAttention、CUDA Graph、连续批处理、前缀缓存（Prefix Caching）、多卡并行（TP/PP/EP）和投机解码。证明在后台异步生成，绝不阻塞流式输出。
2. **不多泄露一点商业机密**：除了标准商业 API 本来就会返回的信息（如可见回复、token 用量统计）之外，不泄露模型权重、真实层数、宽度、是不是 MoE 及专家路由、部署精度、隐藏系统提示词和隐藏思维链（CoT）原文。

### 三步工作流程

- **上线时做一次承诺（Commit）**：服务商发布模型时，公布一个密码学承诺标识 `model_id` 和一份一次性设置证明，把真实权重、各算子的浮点舍入误差上限、隐藏提示词和采样密钥锁死。权重只需编码一次，后续证明在电路内部秘密读取所需列，整个服务生命周期内**永远不会用完作废**。
- **回复后在后台抽查出证（Prove）**：在线推理时，只读钩子顺手记下各计算块输入输出的轻量摘要。流式回复发完后，后台工作进程按算力成本比例随机抽查 315 个计算块和生成步，在零知识电路内验证它们与承诺模型一致（误差落在硬件算子声明的浮点舍入范围之内）。证明开销只跟抽查次数有关，与模型总层数脱钩，不再是推理本身的几十倍。
- **任何人在普通 CPU 上验证（Verify）**：用户或任何第三方拿到 `model_id`、请求、可见回复和证明文件，在普通笔记本 CPU 上花一两秒就能独立验出真伪，既不需要模型权重，也不需要信任服务商或硬件厂商（无需 TEE）。

> **当前版本说明（`v0.2.0`，Stage 0）：** 本仓库按验证完成的阶段逐步公开。当前的 Stage 0 发布完整协议规范（[`specs/01`–`10`](specs/README.md)）、英文技术论文（[`paper/flashprove-next.pdf`](paper/flashprove-next.pdf)）、可独立编译验证的 Lean 4 证明库（[`lean/`](lean/THEOREM.md)）、真实模型硬件实测数据（[`benchmarks/certified/`](benchmarks/certified/README.md)）以及双语展示页（[`docs/`](docs/index.html)）。独立 CPU 验证器程序、真实模型证明样本包和 vLLM 无侵入插件将在 Stage 1 发布。

## 相比 FlashProve 往前走了哪几步

Anthropic 的 **[FlashProve](https://github.com/anthropics/FlashProve)** 首次验证了在 400B 闭源 MoE 模型上“不靠硬件飞地、不泄权重”做零知识推理证明是可行的，但也清楚暴露了为什么传统全量 zkML 没法直接搬上生产 API：

| 对比维度 | FlashProve (2026-11) | FlashProve-Next |
|---|---|---|
| **承诺的是真模型吗？** | **不是（整数替身模型）**：把 4-bit 权重转成确定性整数模型来证；其报告实测线上原生浮点跑出的 96 条诚实回复里，0 条能通过精确匹配 | **是线上真身**：直接承诺实际部署的 `bf16`/`fp8` 权重、算子舍入误差规则、隐藏提示词与采样密钥 |
| **推理系统受限制吗？** | **严重受限**：只支持贪心或固定种子确定性整数解码；跑全尺寸演示需先停掉 vLLM 服务 | **零侵入**：照常跑原生浮点、随机采样、FlashAttention、CUDA Graph、连续批处理、多卡并行与投机解码 |
| **商业 API 隐私够严吗？** | 只藏权重；层数、宽度、MoE 结构公开；不支持隐藏系统提示词、隐藏思维链与多轮加密状态 | 权重、层数、宽度、MoE/MLA/线性注意力结构、精度格式、隐藏提示词、隐藏 CoT 与跨轮状态全部隐藏 |
| **模型承诺会过期吗？** | **会耗尽**：掩码权重表最多用 688,127 个批次就彻底耗尽，必须换新 ID 重做且无法公开关联 | **永不耗尽**：静态编码一次，每次证明在电路内秘密打开列，任意多次出证都不泄露静态码字 |
| **出证算力成本多高？** | **逐层全量重证**：每张 H100 出证耗时是 8×H100 vLLM 预填充的 **72–94 倍**，无法默认常开 | **按成本加权抽查**：只证固定抽查样本（默认三池共 315 次），复杂度与层数解耦，向常态开启推进 |

## 目前已经验证了什么（实事求是区分）

我们严格区分**机器已经检验的定理**、**真卡跑出来的实测数据**，以及**还在纸面或下一阶段要做的工作**：

### 1. 已由 Lean 4 机器检验的定理（`lean/`，18 个模块、194 条声明，零 `sorry`）
在 Lean `4.29.1` + Mathlib 上编译通过，只依赖 Lean 标准三条公理：
- **抗全生命周期刷随机数的可靠性（`RoundByRound`、`LifetimeSoundness`、`ProtocolBridge`）**：哪怕恶意服务商在整个服务生命周期内做满 $Q = 2^{64}$ 次哈希查询（反复换盐、放弃重算、挑有利挑战），只要某条回复里偷工减料的计算块成本占比达到 $\sigma=0.5$，或者违规采样的 token 占比达到 $\rho=0.5$，每个抽查池各抽 105 次（输入计算、生成计算、采样三池共 315 次）就能把漏网概率压在 $2^{-40}$（约一万亿分之一）以下。从协议规范到这套逐轮计数的完整推导链与扩域 $\mathbb F_{p^3}$ 参数门槛均已机检。
- **分桶随机采样的完备性（`BucketSampling`）**：证明无需排序的整数分桶温度 / top-$p$ 采样规则在任意温度 $T>0$、任意 $p_{\rm top}\in(0,1]$（含平局和下溢极端情况）下，诚实引擎采出的 token 100% 通过验证，不会出现误拒；同时证明电路里的边界对检查没有任何可被作弊者钻空子的松弛余量。
- **零知识盲化与多架构等价性（`MaskJoint`、`Gadgets`、`Speculative`、`LinearAttn`、`ArchGeneral`）**：机检了多轮证明中每轮消息严格依赖前序消息时的精确均匀分布（保证模拟视图与秘密完全独立）、Libra 求和掩码双射、MoE 成对带宽路由、耦合投机解码对任意不可信草稿模型的严格等价性，以及 MLA 矩阵吸收、分块线性注意力与流水线/专家并行的代数恒等式。

### 2. 已在真实模型和 GPU 上实测的数据（`benchmarks/certified/`，RTX 4070 Ti SUPER 16 GB）
- **诚实原生浮点推理“零误拒”**：在完整未裁切的 `Qwen3-0.6B`（**249,384 个算子块**）和 `Llama-3.2-1B-Instruct`（**143,544 个算子块**）上运行原生 `bf16` + FlashAttention-2（开启 `fp32` 累加归约），**坏块数为 0**。这至关重要——如果诚实推理偶尔因为浮点误差出不了证明，“能不能出证”本身就会泄露内部激活信息。同一组测试还抓出了 PyTorch 默认开启 `bf16` split-K 归约时在长上下文预填充阶段高达 39 倍的精度违约。
- **8 类常见省算力作弊检出率 97.3%–100%**：在 `Qwen3-0.6B` 上实测了偷换小模型（`Qwen2.5-0.5B`）、`int4` 量化、同权重转 `fp8 W8A16`、`fp8 W8A8`、低秩剪枝、隔层跳层、填零绕过跳层（zero-chain）、以及滑动窗口截断历史 KV 共 8 种作弊。按子层谱系追责规则（深度 $h=3$），所有作弊模式的坏计算成本占比均高达 **97.3%–100%**，远超 50% 的拦截线；作为对比，如果只在层与层之间检查，同权重转 `fp8`（仅检出 3.3%）和截断上下文（0%）都会漏网。
- **坦诚公开“低于浮点舍入量级的长上下文丢键边界”**：在超长上下文里，如果某些历史位置注意力权重小到连 `bf16` 舍入都留不下痕迹，任何不误杀诚实推理的容差都无法区分它和正常舍入。我们在 `Qwen3-4B`（4k–32k 上下文）上实测了全知视角下的理论最大省算比例（12.4%–55.1%；顺手记录 FlashAttention 原本就会算出的标量 LSE 后可压低一半至 **5.9%–36.6%**）。我们不夸大宣传能防住这一项，而是要求每个 `model_id` 按上下文长度如实公布这个上界。

### 3. 仍在纸面或留待下一阶段完成的部分
- Basefold 多项式承诺本身的邻近可靠性假设、具体电路生成代码与 Lean 抽象约束系统的机械对接、多证明随机预言机编程归约以及实数浮点误差传播公式，目前由论文与规范中的数学证明和上述 39 万块硬件实测共同支撑。
- 线性注意力并行扫描（`Scan`）的浮点误差模板，以及在 Hopper/Blackwell 真 FP8 Tensor Core、TPU、Trainium 上的内核标定留待后续阶段实测。

### 一键核验全部 Lean 4 证明

需安装 [`elan`](https://github.com/leanprover/elan)（会自动按 `lean/lean-toolchain` 选用 Lean `4.29.1`）：

```bash
cd lean
lake exe cache get
bash check.sh
```

最后一行输出 `OK: all 18 modules verified, no sorry, only standard axioms` 即代表全量通过。

### 重新编译论文 PDF

需安装 Python 3 与 [`tectonic`](https://tectonic-typesetting.github.io/)：

```bash
python3 paper/md2tex.py paper/flashprove-next.md paper/flashprove-next.tex
cd paper && tectonic flashprove-next.tex
```
