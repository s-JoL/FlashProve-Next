## Why This Exists

When you call a closed-weight LLM API, you have no cryptographic proof of what ran behind the endpoint: whether the server routed your request to a smaller model under load, quantized a `bf16` checkpoint to `int4`, skipped layers, truncated context, or shortened a hidden system prompt to save reasoning tokens.

FlashProve-Next attaches a verifiable zero-knowledge-masked proof to an API response under two constraints:

1. **Keep production serving intact.** No fixed-point surrogate model and no deterministic-integer rewrite. Inference runs in native floating point (`bf16`/`fp8`/`mxfp4` with `fp32` GEMM reductions), with temperature/top-$p$ sampling, FlashAttention, CUDA Graphs, continuous batching, and prefix caching. Proving runs asynchronously after streaming finishes.
2. **Protect serving secrets.** The proof hides model weights, hidden system prompts, hidden chain-of-thought (`CoT`) text, intermediate activations, and multi-turn encrypted state. In `v1.0.0`, dense full-reply profiles still expose coarse geometry (layer/width tier); cross-architecture hidden-table privacy is deferred to `v2`.

## Try It on Any Laptop CPU (No GPU, No Model Weights)

### 1. Rust `FPN2` verifier (`~10 ms` per `8 MiB` container)

Verify an exact `8,388,608 B` zero-padded `FPN2` container (`fpn2-llm-std-v1`, `Q = 72`, 64-row reference circuit) using both the zero-dependency `#![forbid(unsafe_code)]` Rust CLI (`core/`) and the detached pure-Python reference (`verifier/python/`, AST-tested for zero prover imports):

```bash
pip install numpy   # needed by the Python harness; Rust fpn-verify has zero dependencies
cargo build --release --manifest-path core/Cargo.toml --bin fpn-verify
python demo/run_v1_relation2_demo.py
```

On an unloaded Apple M1 CPU, the honest `8 MiB` container verifies in ~`10 ms` (warm Rust CLI) and ~`110 ms` (Python), while all 8 negative checks (`E_CIRCUIT_UNPINNED`, `E_CIRCUIT_PINNED`, `E_STMT_UNPINNED`, `E_STMT_PINNED`, `E_PADDING`, `E_LENGTH`, gate forgery `E_SUMCHECK`, range forgery `E_GKR_ROOT`) reject identically across both verifiers and re-proving shares 0 aligned 64-byte private blocks.

### 2. Real `Qwen3-0.6B` API proof bundles (`demo/run_demo.py`)

Verify bundled proofs (`Stage 1` `FPNZK1` gzip format, ~`10.1 MiB` each) generated by unsliced `Qwen/Qwen3-0.6B` (`L = 28, d = 1024, V = 151,936`) on live `vLLM 0.33` (`CUDA_VISIBLE_DEVICES=""` is enforced automatically; ~`30–145 s` total on Apple M1 depending on CPU load):

```bash
pip install -e ".[tokenizers]"
python -m flashprove_next.build_ext   # optional C++ Goldilocks speedup; pure NumPy works too
python demo/run_demo.py
```

Checks 3 honest replies (`VERIFIED`: hidden system prompt + hidden `<think>` CoT, Turn-1 multi-turn `St_prev -> St_new` chain, strict JSON-Schema constrained decoding) and 6 attacks (`REJECTED`: live `int4`-quantized server, missing `--allow-reduced-security`, altered reply token, replayed nonce, tampered `St_prev`, injected schema). Bundled proofs use the compact `qwen3-0.6b-demo` profile (`4 + 2` draws); production profiles use `NI-315` (`210 + 105`) or `ExtSeed-153` (`102 + 51`).

One boundary is worth stating upfront: in `v1.0.0`, the zero-dependency Rust binary verifies self-contained `FPN2` containers (Relations 1–6), whereas full 12-round interactive LLM replies (`FPNZK2`) still run through the Python verifier.

## Comparison with FlashProve

Anthropic's [FlashProve](https://github.com/anthropics/FlashProve) showed that closed-weight 400B MoE inference can be proved without hardware enclaves by proving exact full-layer execution of a deterministic 4-bit integer surrogate. FlashProve-Next targets a different point in the design space: keeping native floating-point production serving unchanged.

| Dimension | FlashProve (2026-11) | FlashProve-Next |
|---|---|---|
| **Guarantee** | Exact full-layer execution of a committed 4-bit integer surrogate | Cost-weighted spot-check threshold ($\sigma = \rho = 0.5$): `NI-315` ($\varepsilon \le 2^{-40}, Q \le 2^{64}$) or external-seed `ExtSeed-153` ($\varepsilon \le 2^{-20}, Q_{\rm samp} \le 2^{30}$ with pre-recorded `C_pre`) |
| **Committed model** | Deterministic 4-bit integer surrogate | Deployed `bf16`/`fp8`/`mxfp4` weights, per-operator rounding bounds, hidden prompts, and sampling key |
| **Serving stack** | Greedy or fixed-seed integer execution across all layers | Native FP (`fp32` GEMM reductions), random temperature/top-$p$ sampling, FlashAttention, CUDA Graph, continuous batching, prefix caching |
| **Privacy** | Weights only; architecture public; no hidden prompts, CoT, or multi-turn state | Weights, hidden prompts, hidden CoT, activations, and multi-turn state (`v1.0.0` dense `reply_zk` fixes coarse geometry per profile; cross-architecture hiding in `v2`) |
| **Commitment lifetime** | Exhausts after 688,127 batches | Non-depleting static RS commitment opened inside proofs (`HCO`, [`specs/09`](specs/09-model-commitment.md)) |
| **Proving structure** | Proves every layer of every token | Proves a fixed cost-weighted sample (`315` or `153` draws), independent of depth $L$ |

### Core Mechanisms

1. **Non-depleting static RS commitment (`HCO`, [`specs/09`](specs/09-model-commitment.md)).** Weights, radius matrices, hidden prompts, and the sampling key are committed once into `model_id` with a one-time setup proof $\pi_{\rm setup}$. Later proofs open touched GEMM tiles inside the circuit with fresh blinding, so the commitment does not wear out.
2. **Single-hop local rounding contracts & lineage billing ([`specs/06`](specs/06-tolerance-and-cheats.md)).** If a surrogate diverges from native FP on even a small fraction of honest requests, the bit "could the server produce a proof?" leaks hidden activations (`paper/flashprove-next.pdf` §9.4). Checking each sampled operator against a local reference from the engine's own committed inputs keeps rounding bounds at single-operator scale, while consumer-lineage billing (`Rule CA`) closes zero-operand layer skipping.
3. **Sort-free bucketed sampling & $\mathbb F_{p^3}$ constrained decoding ([`BucketSampling.lean`](lean/FlashProveNext/BucketSampling.lean), [`ConstrainedMask.lean`](lean/FlashProveNext/ConstrainedMask.lean)).** Replaces full-vocabulary sorting with 32-token buckets and a witness-free top-$p$ sandwich (`sure`/`poss`), and binds compiled JSON-Schema byte-DFA masks over a 151,936-token vocabulary in $O(k_2 Q_{\rm pad})$ cells via multilinear Schwartz–Zippel ($\le 2^{-186}$).
4. **Zero-Phase-2 folded backend (`multi_gkr` + `multi_pcs` + `folded_engine`).** Replaces Stage 1's `2.36B`-cell Phase-2 LogUp inverse commitments with batched ZK-masked FracLogUp-GKR (using independent $(0, d_L)/(0, d_R)$ layer-0 denominator blinders) and multi-size layer-injected rate-$1/8$ coset-4 folded ZK-Basefold.

### 3. Lean 4 Formalization (`lean/`, 28 Modules, 696 Axiom-Audited Declarations, Zero `sorry`)

Verified on Lean `4.29.1` + Mathlib via `lean/check.sh` with `native_decide` forbidden and only the three standard axioms (`propext`, `Classical.choice`, `Quot.sound`):
- **19 protocol modules (219 audited declarations):** round-by-round lifetime soundness composition (`RoundByRound`, `LifetimeSoundness`, `ProtocolBridge`), all 16 sample-count table cells, multi-column LogUp, bucketed top-$p$ sampling (`BucketSampling`), $\mathbb F_{p^3}$ constrained-mask binding (`ConstrainedMask`), causal multi-round masking (`MaskJoint`), and algebraic identities for MoE, MLA, linear attention, and speculative decoding.
- **9 `FPN2` modules (477 audited declarations):** Mathlib-free executable byte verifiers (`VerifyBytes`, `Fpn2Rel3`–`5`, matching all `131/131` golden vectors + `26/26` multi-tile cases), concrete Goldilocks $\mathbb F_{p^3}$ soundness (`Fpn2Soundness`), constraint-to-integer proofs for 6 IR gadget families (`Fpn2Gadgets`), and conditional `ProtocolRBRSpec` instantiation at `verifyBytesRel4`/`5` (`Fpn2EndToEnd`, see [`lean/THEOREM.md`](lean/THEOREM.md) §2.4 for exact `CryptoAssumptions` and `Delta` caveats).

### 4. Known Boundaries & Next Work (`v2`)

- **Rust single-binary verification of full replies:** lower `reply_zk`'s 12 interactive commit rounds into a self-contained `CircuitDesc`.
- **Folded-prover host RAM & 4B+ production draws:** restore `~1.5 B/cell` streaming to bring `100 GiB` folded RSS back toward Stage 1's `21 GiB`, and run production draws on 4B and 30B+ closed-weight models.
- **Formalization & ZK proofs:** complete Johnson-regime RBR for multi-size injection (`A-PCS-fold`; bypassed at `Q >= 128`), write a transcript-wide ZK simulator for the folded backend, add Lean verifiers for Relations 2 and 6, and mechanically connect Python circuit synthesis to `CompiledCS`.
- **Cross-architecture hiding:** replace per-profile dense geometry with uniform hidden-table slots across Dense GQA, Sparse MoE, MLA, SWA, and linear attention.
