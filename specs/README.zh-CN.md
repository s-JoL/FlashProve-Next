## 十份规范分别解决什么问题？

### 1. [`01-relation.md`](01-relation.md) —— 单次 API 回复到底在证明什么？
定义验证器最终验收的数学陈述：
- **输入与输出绑定**：把公开请求（含多模态字节、JSON Schema、停止串、客户端随机数 $N_c$）、服务端隐藏注入内容（系统提示词、工具模板、思考预算）与最终可见回复一一对齐，杜绝拼接与重放。
- **张量连线没有任何可自由改动的余地**：跨算子传递的激活值和 KV 缓存作为不可变对象写入加盐海绵 Merkle 树，产生方和消费方按确定性地址读取同一个叶子，证明者无法中途偷换中间结果。
- **输入层与生成层分池抽查（$\Pi_2$）**：防止服务商利用“一万字长提示词 + 五百字短回复”稀释解码阶段的偷工减料；输入计算、生成计算与 token 采样分三个独立池抽查。
- **无环多轮对话状态链**：把可见核心回复与外层证明信封拆开哈希，使加密回传的隐藏思维链（CoT）能跨轮验证而不产生循环哈希依赖。

### 2. [`02-soundness.md`](02-soundness.md) —— 为什么恶意服务商刷 $2^{64}$ 次随机数也混不过去？
- **无需重绕的直线提取器**：由于承诺叶子在电路内用 Poseidon2 海绵吸收了完整张量，提取器只需扫描哈希查询表即可还原出服务商提交前的完整计算轨迹（缺失原像直接记为坏块），不产生指数级重绕损失。
- **逐轮可靠性（抗自适应反复试算）**：多轮 Fiat–Shamir 协议不能简单对前缀取并集（否则攻击者固定一次侥幸前缀后可以专刷后续轮次）。我们定义每轮的“注定失败状态（Doomed State）”，证明在三次扩域 $\mathbb F_{p^3}$ 下，跨越抽样、Sumcheck、多列 LogUp、模型列打开与 Basefold 全部轮次的总伪造概率不超过 $2^{-40}$（每池抽查 $k=105$ 次，三池共 $315$ 次；定理主干在 [`ProtocolBridge.lean`](../lean/FlashProveNext/ProtocolBridge.lean) 与 [`RoundByRound.lean`](../lean/FlashProveNext/RoundByRound.lean) 中机器证明）。

### 3. [`03-zero-knowledge.md`](03-zero-knowledge.md) —— 为什么不会多泄露标准 API 之外的一点秘密？
- **显式信息边界**：证明模拟器仅凭标准商业 API 原本返回的内容（请求、可见文本、包含隐藏思考长度在内的用量计数）、公开 `model_id` 与公开停机日志，就能生成与真实证明在统计/计算上不可区分的视图。
- **彻底封堵侧信道**：证明体积按公开档位固定填充，证明在固定截止时间释放，空回复（`max_tokens=0`）对轨迹根额外加盐，多轮证明各用一次性随机掩码并在释放后立即销毁。

### 4. [`04-completeness.md`](04-completeness.md) —— 为什么诚实的原生浮点推理不会误拒？
如果某些正常请求因为浮点舍入误差偶尔出不了证明，“能不能出证”这一位就会泄露模型内部激活。我们将完备性拆成三层：
- **代数完备性**：唯一可能碰撞的 LogUp 分母极点概率低于 $2^{-138}$，换新掩码重试即可消除；
- **数值零误拒**：只要线上算子满足预先声明的舍入误差规则（`H-contract`），哪怕面对恶意构造的极端对抗提示词，诚实推理也 100% 落在电路算出的允许误差之内（$\varepsilon_{\rm num}=0$）；
- **资源故障公开窗口**：机器崩溃或超时等与输入秘密无关的运维故障统一按分区公开停机窗口处理，绝不让单条请求因内部数值原因静默失败。

### 5. [`05-computation-model.md`](05-computation-model.md) —— 怎么做到完全不改现有生产推理系统？
将“逻辑计算图”与“物理内核实现模板”解耦：
- **主流架构全覆盖**：统一支持稠密 GQA、稀疏 MoE、DeepSeek 式矩阵吸收 MLA、滑窗注意力（SWA + Sink）与分块线性注意力（Gated DeltaNet / Mamba-2）；
- **生产加速全兼容**：连续批处理、PagedAttention 前缀缓存、张量/流水线/专家并行（TP/PP/EP）、预填充与解码分离（P/D 分离）以及耦合投机解码均可原样开启，无需为出证改写底层算子。

### 6. [`06-tolerance-and-cheats.md`](06-tolerance-and-cheats.md) —— 算子误差怎么传播？常见省算力作弊怎么抓？
- **只在单个算子内传播误差**：不在多层之间累积浮点误差，而是对被抽查的每个矩阵乘（GEMM）或注意力块，直接从引擎自己记录的输入出发推导一步允许误差（包含 FlashAttention 在线缩放与指数下溢项）。
- **免排序分桶随机采样（`fpn-samp-bk-v3`）**：把词表按 32 词分桶，用带密钥海绵生成桶级 Gumbel 噪声并在桶内做逆变换采样，免去全词表排序，把采样电路缩小约 10 倍，且在 Lean 4（[`BucketSampling.lean`](../lean/FlashProveNext/BucketSampling.lean)）中证明了对任意温度与 top-$p$ 都不会误拒诚实采样。
- **子层谱系追责（防填零跳层漏洞）**：实测发现，如果跳过一层并故意往后续矩阵乘塞全零输入（$W\cdot 0 = 0$），单纯按算子块计价会让 38% 的跳层省算只暴露万分之一的坏块。通过按子层计价并沿因果依赖链追责 3 层（$h=3$），8 类现实作弊的违规成本占比全部拉升至 **97.3%–100%**。

### 7. [`07-assumptions-and-lean.md`](07-assumptions-and-lean.md) —— 全部 30 项前提假设与 Lean 4 对照图
把全部前提分为密码学（11 项）、数值（7 项）、工程（6 项）与明确边界（6 项），给出完整依赖关系图，证明**防伪造可靠性只依赖密码学假设与协议实现义务，与算子数值合约无关**（算子数值合约只影响诚实方能否出证，绝不会放过作弊者），并逐条映射到 19 个协议层 Lean 模块。

### 8. [`08-related-work.md`](08-related-work.md) —— 与现有方案的系统对比
对比全量零知识证明（ZKML、zkLLM、zkGPT、FlashProve）、抽样层证明（SLP）、需要持有权重的激活指纹重算（TOPLOC、DiFR、FSSL、SVIP）、多副本仲裁（Verde）以及硬件可信执行环境（GPU TEE）。

### 9. [`09-model-commitment.md`](09-model-commitment.md) —— 一次性静态模型承诺（不会因出证次数耗尽）
证明任何在公开证明里直接打开静态码字的哈希承诺都会在有限次请求后泄露权重（静态码字耗尽引理）。为此将模型权重与误差半径矩阵编码为 Reed–Solomon 交织矩阵，发布时附一份一次性设置证明 $\pi_{\rm setup}$，每次回复证明在零知识电路内部秘密打开 123 列并同时打开模型配置表，不会随出证次数磨损。

### 10. [`10-trace-commitment.md`](10-trace-commitment.md) —— 长上下文 KV 历史矩阵承诺
在 4k–32k 长上下文下，如果在电路内逐个打开历史 KV 的海绵叶子，电路规模会膨胀到单机内存放不下。通过承诺前定点提升、每请求异步构建 KV 纠错码矩阵、隐藏选择求和归约（Hidden-Selection Sumcheck）以及公开 2 的幂长度分档，把注意力历史读取压回单机可承受的规模。

### 11. [`11-wire-format.md`](11-wire-format.md) —— `FPN2` 字节级线格式（`v0.3.0` 之后开发树新增的实现层规范）
逐字节规定 `FPN2` 证明容器与规范化配置档编码、直接吸收原始线上字节的 Fiat–Shamir 转录、线格式关系 1 与 3–6 的证明体布局，以及验证器必须遵循的检查顺序与拒绝码；[`vectors/`](vectors/) 中的标准测试向量由 Rust 与 Python 两套验证器共同核对。
