# Spec 03: Adaptive Multi-Proof Zero Knowledge & Explicit Leakage (`fpn-zk-1.0`)

**Specification ID:** `fpn-zk-1.0` | **Role:** Explicit leakage function $\mathcal L = \mathcal L_{\mathrm{API}} \cup \mathcal L_{\mathrm{pub}}$, fixed-length envelope simulation, causal multi-round masking, and secret lifecycle

---

## Overview and Architectural Motivation

For a commercial closed-weight LLM provider, adopting verifiable inference is viable only if attaching proofs reveals **zero bits of proprietary information** beyond what an unmodified API already returns—protecting model weights, layer count, hidden width, MoE expert topology and active routing, deployed floating-point precision, hidden system prompts, private chain-of-thought (`CoT`) reasoning, co-batched tenant traffic, and even the single bit of whether a given prompt came close to failing proof generation.

`fpn-zk-1.0` formalizes adaptive, multi-proof, multi-tenant zero knowledge across an entire service lifetime:

1. **Strict explicit leakage boundary $\mathcal L = \mathcal L_{\mathrm{API}} \cup \mathcal L_{\mathrm{pub}}$.** $\mathcal L_{\mathrm{API}}$ contains exclusively the fields returned by an unmodified commercial API, while $\mathcal L_{\mathrm{pub}}$ adds only public `model_id` rotation events, the public capability/size profile $\mathrm{Prof}$, the public service policy $\Phi$, and the public partition outage log $\mathcal O$ (§2). Global request counters and server-side monotonic sequence numbers are prohibited because differences across consecutive responses leak cross-tenant request volume; per-request freshness instead uses an independent $256$-bit server random value $N_s$ ([Spec 01](01-relation.md) §5.5).
2. **Simulated fixed-shape proof envelopes.** Every artifact introduced by FlashProve-Next—$N_s$, `proof_id`, trajectory root $R$ (with $256$-bit root salt $\varsigma_R$), state anchor $\mathsf{St}_{\rm new}$, fixed-length encrypted state `blob`, fixed-length setup certificate container, $\mathsf{cm}_{\rm glob}$, fixed-size proof container $S_{\mathrm{Prof}}$, release timestamps, failure codes, and endpoint replies—is generated by the zero-knowledge simulator without access to any secret (§2.3). Stratum costs $C_j$, empty-stratum flags, sampled atom coordinates, and lineage blocks remain strictly inside the circuit.
3. **Bottom-up Merkle simulation without tree programming.** For each simulated proof, $\mathcal S$ first samples all Fiat–Shamir challenges uniformly, invokes the IOP honest-verifier simulator to draw a joint affine view satisfying every verifier equation simultaneously, places salted simulated values at queried PCS leaves and uniform strings at unqueried leaves, and computes Merkle roots **honestly bottom-up** (§4.1). Authentication paths are automatically consistent with roots without programming internal Merkle hashes; $H_{\rm out}$ is programmed exclusively at Fiat–Shamir challenge inputs.
4. **Witness-free hybrid ordering.** The hybrid reduction replaces real proofs with witness-free simulated proofs *first*, replaces salted commitments (`model_id`, $R$, $\mathsf{St}_{\rm new}$) with uniform digests *second*, replaces failure/endpoint transcripts *third*, and replaces $\mathsf{PRF}_{K_{\rm prf}}$ with a true random function *last* (§4.2). By the final step, $K_{\rm prf}$ appears only inside engine sampling—never inside commitments or proof witnesses—allowing a clean black-box PRF reduction even when random-function outputs have no valid witness under any committed key.
5. **Release-order causal multi-proof composition.** Proofs are ordered by atomic release timestamps and replaced inductively using fresh per-attempt CSPRNG masks whose round shifts satisfy strict prefix causality (`[Lean: MaskJoint.causal_transcript_existsUnique]`, `[Lean: MaskJoint.multiround_independent_causal]`, §4.3).
6. **Protecting the provability bit.** Lifetime distinguishing advantage is bounded by $\approx 2^{-88} + \delta_{\mathrm{num}} + \delta_{\mathrm{flt}}$ (Theorem 4.1). Achieving $\delta_{\mathrm{num}} = 0$ relies strictly on certified-tolerance numerical completeness under `H-contract` ([Spec 04](04-completeness.md) Corollary 3.1): converting an online secret-dependent numerical violation into a public outage would still reveal that hidden activations overflowed tolerance (§4.6). Resource faults independent of secrets satisfy $\delta_{\mathrm{flt}} = 0$ via declarative failure closure (`R9`).
7. **Unified Poseidon2 keyed-sponge PRF.** Evaluating bucketed sampling noise via a domain-separated Poseidon2 keyed sponge in the same ideal-permutation model reduces in-circuit PRF work from $\approx 2^{27.6}$ to $\approx 2^{21.8}$ S-boxes per proof while keeping $H_{\rm out}$ (BLAKE3/SHA-3) completely separate for ROM programming (§5.4).

## 1. Parties and Threat Model

`[Def]`
- **Provider $P$:** Across key epochs $e = 1, 2, \dots$, $P$ holds configuration $M_e$ and secret randomness. Per [Spec 09](09-model-commitment.md), $\mathsf{model\_id}_e = H_{\rm in}(\texttt{dom}_{\rm mid}, \varsigma_0, \mathsf C_W, \mathsf C_{\rm raw}, \mathsf C_{\rm cfg})$, where $\mathsf C_W, \mathsf C_{\rm raw}$ commit Reed–Solomon weight columns with $256$-bit per-column salts $\varsigma_j$ and $\mathsf C_{\rm cfg}$ commits volatile metadata (hidden prompt injections, sampling parameters, and $K_{\rm prf}$). Each request draws fresh trajectory leaf salts, root salt $\varsigma_R$, state-anchor randomness $r_i$, and $N_s$; each proof attempt draws fresh blinding randomness $\omega^\pi$.
- **Tenants $\tau$:** Issue API requests and receive responses and proofs. Because tenants may publish or forward proofs, zero knowledge holds against **any** holder of $(X, \pi)$.
- **Adversary $\mathcal A$:** Adaptively corrupts an arbitrary subset of tenants; chooses requests for corrupted tenants (including chosen $N_c$, repeated prompts, adversarial inputs, stream cancellations, and prefix claims); schedules honest-tenant requests without observing honest-tenant outputs; observes all corrupted-tenant views and all public events; and makes up to $q_H$ queries to $H_{\rm out}$ and $q_P$ queries to $P^{\pm 1}$. *(For zero knowledge, the adversary is an external observer or malicious client, whereas provider dishonesty is governed by [Spec 02](02-soundness.md).)*
- **Out of scope:** (i) Information inherent in input–output behavior of the unmodified API itself (black-box model distillation); and (ii) out-of-band provider operational breaches, whose blast radius is analyzed separately in §5.2.

### 2.2 $\mathcal L_{\mathrm{pub}}$: Protocol-Level Public Objects

`[Def]` $\mathcal L_{\mathrm{pub}}$ adds four secret-independent public protocol objects:
- **Model rotation timestamps and epoch bindings:** Publication timestamp of each `model_id` and the epoch $e$ bound to each admitted request ([Spec 04](04-completeness.md) `R11`). Both the digest `model_id` and its setup certificate are generated by $\mathcal S$; **whether a rotation changed weights or only rotated volatile prompts/keys is NOT in $\mathcal L$** (§2.3).
- **Public profile $\mathrm{Prof}$:** Field and PCS parameters, worst-case contract envelope $\mathcal C_{\max}$ ([Spec 06](06-tolerance-and-cheats.md) §1.2), stratification rule $\Pi$ and sample counts $(k_{1,j}, k_2)$, lineage depth $h$, architecture upper bounds ($L_{\max}, V_{\max}, R_{\max}, U_{\rm slot}$), $T_{\mathrm{pad}}$, proof deadline interval $\Delta_{\rm rel}$, retry cap $J$, claim/retention windows $(W_{\mathrm{claim}}, W_{\mathrm{ret}})$, and fixed proof byte size $S_{\mathrm{Prof}}$.
- **Public service policy:** Deterministic pre-/post-request policy predicate $\Phi$, public reason codes, release schedule, and endpoint state machine ([Spec 04](04-completeness.md) §5, §7).
- **Public outage log $\mathcal O$ ([Spec 04](04-completeness.md) §6):** Timestamped outage windows declared per public serving partition (region or tier) applying uniformly to all tenants in that partition, independent of request contents or model secrets.

**Excluded from $\mathcal L$:** Global request counters, cross-tenant monotonic sequence numbers, batch composition, and prover worker assignments.

## 3. Formal Zero-Knowledge Security Definition

### 3.1 Ideal API Functionality $\mathcal F_{\mathrm{API}}$

`[Def]` $\mathcal F_{\mathrm{API}}$ internally executes the provider's serving engine $\mathsf{Eng}$ (scheduling, continuous batching, cache isolation, native timing, and native HTTP errors) on configurations $(M_e)_e$ with exactly two modifications relative to the real deployment:
1. **No proof-system hooks or provers:** FlashProve-Next online boundary capture and background proving daemons are absent.
2. **True random sampling variates:** Sampling noise replaces $\mathsf{PRF}_{K_{\rm prf}}$ with an independent true random function $\mathsf{RF}_e$ per epoch, passed through the **identical committed discrete maps** $(\mathsf G, \mathsf U)$ ([Spec 01](01-relation.md) §5.3, [Spec 06](06-tolerance-and-cheats.md) §3.1), so the ideal token distribution equals the exact specification distribution with zero modular conversion bias.

For each request $i$, $\mathcal F_{\mathrm{API}}$ outputs $\mathcal L_{\mathrm{API},i}$, along with global public events $\mathcal L_{\mathrm{pub}}$.

### 3.2 Real vs. Ideal Lifetime Indistinguishability Game

`[Def]`
- **Real experiment $\mathsf{Real}_{\mathcal A}$:** $\mathcal A$ adaptively chooses the sequence of model configurations $(M_e)_e$ and epoch switch times (Because $\mathcal A$ chooses and knows $M_e$, indistinguishability simultaneously protects $M_e$ and all per-epoch/per-request randomness). The challenger generates all secrets, `model_id` digests, setup certificates, PRF-sampled responses, envelope fields, proofs, release schedules, and real proving-cluster failure/outage events (`R9`). $\mathcal A$ adaptively queries $H_{\rm out}$ and $P^{\pm 1}$, issues corrupted-tenant requests and proof-endpoint polls, schedules honest-tenant requests, and adaptively corrupts additional tenants, finally outputting a bit.
- **Ideal experiment $\mathsf{Ideal}_{\mathcal A, \mathcal S}$:** Responses and leakage $\mathcal L$ are produced by $\mathcal F_{\mathrm{API}}$. The simulator $\mathcal S$ receives **only** $(\mathcal L_{\mathrm{API},i})_{i \in \mathrm{Corrupted}}$, corrupted-tenant client actions, and $\mathcal L_{\mathrm{pub}}$; $\mathcal S$ controls $H_{\rm out}$ (programmable) and has black-box query access to $P^{\pm 1}$ (never programming $P$).

**Definition 3.1 (Adaptive Multi-Proof Multi-Tenant $\delta$-Zero Knowledge).** The protocol satisfies $\delta$-zero knowledge for leakage $\mathcal L$ if there exists an efficient simulator $\mathcal S$ such that for every adversary $\mathcal A$ making $\le q_H$ queries to $H_{\rm out}$, $\le q_P$ queries to $P^{\pm 1}$, and triggering $\le N_\pi$ released proofs (with computational boundedness invoked solely for PRF and AEAD reductions),

$$
\bigl|\Pr[\mathsf{Real}_{\mathcal A} = 1] - \Pr[\mathsf{Ideal}_{\mathcal A, \mathcal S} = 1]\bigr| \le \delta.
$$

The lifetime target is $\delta \le 2^{-40}$.

### 3.3 Transcript Zero Knowledge vs. Streaming-Timestamp Zero Knowledge

`[Def]`
- **Transcript zero knowledge** covers $\mathcal A$'s entire view excluding intra-response token streaming timestamps $\Theta$ (encompassing all responses, envelope fields, proofs, release timestamps, endpoint responses, and outage logs). Theorem 4.1 proves transcript zero knowledge unconditionally under `(A1)`–`(A6)`.
- **End-to-end streaming-timestamp zero knowledge** additionally includes $\Theta$. Because $\mathsf{Real}$ runs online capture hooks whereas $\mathcal F_{\mathrm{API}}$ runs an unhooked engine, matching $\Theta$ requires the explicit operational premise `H-hook` (§4.7); we never define $\mathcal F_{\mathrm{API}}$ relative to an already-hooked engine, which would tautologically mask hook timing side channels.

## 4. Main Zero-Knowledge Theorem and Simulator Construction

**Theorem 4.1 (Lifetime Adaptive Zero Knowledge)** `[Paper]` *(core masking algebraic theorems mechanized in `[Lean: Mask.masked_view_independent]`, `[Lean: MaskJoint.multiround_independent_causal]`, and `[Lean: MaskJoint.libra_mask_bijOn_hyperplane]`; multi-proof ROM hybrid composition proved below)*: *Assume:*
- **(A1)** $H_{\rm out}$ is a $256$-bit programmable random oracle instantiated via an independent BLAKE3 or SHA-3 instance sharing no permutation with Poseidon2;
- **(A2)** Poseidon2 permutation $P$ is an ideal invertible permutation over which $H_{\rm in}$ and $\mathsf{PRF}_{K_{\rm prf}}$ are domain- and IV-separated sponges (§5.4) with $\ge 256$-bit salts and keys (matching [Spec 02](02-soundness.md) §1 without invoking `A-AROM`);
- **(A3) IOP Honest-Verifier Zero Knowledge:** For the frozen transcript of [Spec 02](02-soundness.md) §4.1 (including [Spec 09](09-model-commitment.md) HCO columns), conditioned on any public statement $X$ and challenges, the joint revealed IOP view (queried codeword symbols, Libra-masked sumcheck polynomials, evaluation claims, and HCO column openings) is uniformly distributed over a non-empty affine subspace determined solely by $(X, \text{challenges})$, except with mask-degeneracy probability $\le \varepsilon_{\mathrm{deg}}$;
- **(A4)** The serving frontend enforces state-machine rules `R1`–`R13` of [Spec 04](04-completeness.md) (specifically declarative resource-failure closure `R9`, per-attempt fresh CSPRNG masks with immediate erasure `R10`, and server-side verification gating `R5`);
- **(A5)** Lifetime secret-dependent numerical rejection probability is $\delta_{\mathrm{num}}$ ([Spec 04](04-completeness.md) §4; $\delta_{\mathrm{num}} = 0$ under `H-contract`);
- **(A6)** Each setup certificate is zero-knowledge with simulation error $\le \delta_{\mathrm{setup}}$, and `blob` encryption satisfies `IND$-CPA`.

*Then across $N_\pi$ released proofs, $N_{\mathrm{req}}$ requests, $N_{\mathrm{mid}}$ model publications, $N_{\mathrm{prog}}$ programmed Fiat–Shamir points, and $N_{\mathrm{com}}$ hiding $H_{\rm in}$ commitments,*

$$
\delta \;\le\; \underbrace{N_\pi\,\varepsilon_{\mathrm{deg}}}_{\text{mask degeneracy}} + \underbrace{\frac{q_H N_{\mathrm{prog}} + N_{\mathrm{prog}}^2}{2^{256}}}_{H_{\rm out}\text{ programming}} + \underbrace{\frac{q_P N_{\mathrm{com}}}{2^{255}}}_{H_{\rm in}\text{ hiding}} + \underbrace{N_\pi J\,\varepsilon_{\mathrm{pole}}}_{\text{pole retry bias}} + \frac{N_{\mathrm{req}}^2}{2^{257}} + \mathsf{Adv}^{\mathrm{PRF}} + N_{\mathrm{mid}}\,\delta_{\mathrm{setup}} + \mathsf{Adv}^{\mathrm{AEAD}} + \delta_{\mathrm{num}} + \delta_{\mathrm{flt}}.
$$

### 4.1 Simulator $\mathcal S$

**On each `model_id` publication event:** Output a uniform $256$-bit `model_id` and run the setup simulator to emit a fixed-length setup certificate container.

**On each corrupted-tenant request $i$:**
1. At the initial stream event, output independent uniform $256$-bit strings $N_s$ and `proof_id`.
2. At stream completion $t^{\mathrm{end}}_i$, output uniform digests $R$ and $\mathsf{St}_{\rm new}$ plus a uniform fixed-length byte string `blob`.
3. Evaluate the deterministic state-machine transition function of [Spec 04](04-completeness.md) §7 on $(\mathcal L_i, \mathcal O, \text{client actions})$ to schedule every endpoint response and release timestamp.
4. Whenever a proof $\pi$ is scheduled for release at $t^{\mathrm{rel}}_i$:
   - **(a) Sample challenges up front:** Draw uniform challenges $c_1, \dots, c_r$ across all rounds of [Spec 02](02-soundness.md) §4.1 ($\mathbb F_{p^3}$ elements, $192$-bit sample seeds, column indices, and Basefold query indices).
   - **(b) Sample joint IOP affine view:** Given $(X, c_1, \dots, c_r)$, sample all revealed IOP values uniformly from the non-empty affine subspace guaranteed by `(A3)`—satisfying sumcheck round consistency, terminal oracle evaluation claims, Basefold folding relations, repeated-query consistency, and HCO column inner products simultaneously.
   - **(c) Build PCS Merkle trees bottom-up:** For every committed PCS oracle, set each queried leaf $\ell_q = H_{\rm out}(\text{fresh } 256\text{-bit salt} \Vert \text{simulated symbol from (b)})$, populate all unqueried leaves with fresh uniform $256$-bit digests, and **hash honestly bottom-up** via $H_{\rm out}$ to obtain the Merkle root. Every opening path is consistent with its root by construction without programming internal tree nodes.
   - **(d) Program Fiat–Shamir challenges:** In round order $\tau = 1, \dots, r$, program $H_{\rm out}(\texttt{dom}_\tau \Vert c_{\tau-1} \Vert \mathsf{Enc}(m_\tau)) := c_\tau$, aborting only if that exact input was already queried by $\mathcal A$ or collided with a prior programmed point (bounded by $(q_H N_{\mathrm{prog}} + N_{\mathrm{prog}}^2)/2^{256}$ since each $m_\tau$ embeds freshly salted Merkle roots).
   - **(e) Pad container:** Serialize and pad $\pi$ to exact byte length $S_{\mathrm{Prof}}$.

Essential to Hybrid $H_4$ below, $\mathcal S$ produces an accepting transcript for **any** public statement $X$—even a witnessless statement—because `(A3)` guarantees the verifier's linear constraint subspace is non-empty for every public input.

### 4.2 Hybrid Sequence

| Hybrid | Modification from Prior Hybrid | Distinguishing Gap | Justification |
|---|---|---|---|
| $H_0$ | Real world $\mathsf{Real}_{\mathcal A}$ | — | — |
| $H_1$ | In atomic proof-release order, replace each released proof with $\mathcal S$'s witness-free simulated proof (§4.1 Step 4) | $N_\pi \varepsilon_{\mathrm{deg}} + \frac{q_H N_{\mathrm{prog}} + N_{\mathrm{prog}}^2}{2^{256}} + N_\pi J \varepsilon_{\mathrm{pole}}$ | `(A1)`, `(A3)`, Lemma 4.2; discarded retries are never released, and LogUp pole retries skew released challenges by $\le J \varepsilon_{\mathrm{pole}}$ ([Spec 04](04-completeness.md) §2) |
| $H_2$ | Replace `model_id` ($\mathsf C_W, \mathsf C_{\rm raw}, \mathsf C_{\rm cfg}$), $R$, and $\mathsf{St}_{\rm new}$ with uniform digests; `blob` with uniform bytes; setup proofs with simulated containers | $\frac{q_P N_{\mathrm{com}}}{2^{255}} + N_{\mathrm{mid}} \delta_{\mathrm{setup}} + \mathsf{Adv}^{\mathrm{AEAD}}$ | `(A2)`, `(A6)`: in $H_1$, response proofs no longer read commitment preimages, leaving pure salted sponge outputs (in two-pass AES-256-CTR $\pi_{\rm setup}$, $\delta_{\mathrm{setup}}$ includes $B_{\mathrm{setup}} \mathsf{Adv}^{\mathrm{PRG}}$ under `A-PRG`, [Spec 09](09-model-commitment.md) §6) |
| $H_3$ | Compute release timestamps, failure codes, and endpoint replies deterministically from $(\mathcal L, \mathcal O, \text{client actions})$ | $\delta_{\mathrm{num}} + \delta_{\mathrm{flt}}$ | [Spec 04](04-completeness.md) Lemma 6; exact except for secret-dependent numerical rejections (`R13`) or undeclared resource faults violating `R9` |
| $H_4$ | Replace engine sampling noise $\mathsf{PRF}_{K_{\rm prf}}$ with true random $\mathsf{RF}_e$ under the identical discrete maps $(\mathsf G, \mathsf U)$ | $\mathsf{Adv}^{\mathrm{PRF}} + \frac{N_{\mathrm{req}}^2}{2^{257}}$ | `(A2)`, Lemma 5.1, §5.4: $K_{\rm prf}$ now appears **solely** in engine sampling; proofs are simulated without witnesses and `model_id` is uniform |
| $H_5$ | Identical to $\mathsf{Ideal}_{\mathcal A, \mathcal S}$ (transcript scope) | $0$ | Engine outputs match $\mathcal F_{\mathrm{API}}$ identically |

*Why hybrid ordering is essential:* Swapping $\mathsf{PRF}_{K_{\rm prf}} \to \mathsf{RF}_e$ before simulating proofs would cause engine-sampled tokens to violate the committed-key sampling relation, preventing an honest prover (or a PRF reduction lacking $K_{\rm prf}$) from constructing real proofs. Simulating proofs from public statements first severs all dependence on $K_{\rm prf}$ inside commitments and witnesses before invoking PRF security.

### 4.3 Adaptive Multi-Proof and Multi-Tenant Composition

`[Paper]` **Induction in atomic release order.** Order all released proofs chronologically by their atomic release timestamps (`R3` ensures no partial proof bytes are observable prior to $t^{\mathrm{rel}}$). Let $\mathcal H_{<j}$ denote the complete public history prior to the $j$-th release—including earlier proofs, envelope digests, all $\mathcal A$ oracle queries/answers, tenant corruptions, and shared secrets as auxiliary input.

**Lemma 4.2 (Causal Multi-Round Masking Uniformity)** `[Lean: MaskJoint.multiround_independent]` `[Lean: MaskJoint.causal_transcript_existsUnique]` `[Lean: MaskJoint.multiround_independent_causal]`: *Suppose proof $j$'s mask $\omega^\pi_j$ is freshly drawn from a CSPRNG independently of weights, other proofs' masks, salts, and $\mathcal A$'s coins, so $\omega^\pi_j$ remains uniform conditioned on $\mathcal H_{<j}$. In round $i$, the prover's message has the form $A_{j,i}(w, t_{j,<i}) + L_{j,i}(r_{j,i})$, where $L_{j,i}$ is a surjective group homomorphism and the shift $A_{j,i}$ is **strictly causal**—depending only on the witness $w$ and the strict transcript prefix $t_{j,<i}$ (never on current or future mask components $r_{j,\ge i}$, ruling out circular shifts such as $A = -L(r)$). Then every $(w, r_j)$ determines a unique transcript $t_j = \mathrm{evalTranscript}(w, r_j)$ whose fiber size $\prod_i (|G_i| / |H_i|)$ is constant across all witnesses $w$ and target transcripts $t_j$, inducing the exact same uniform transcript distribution for every witness.*

- **Shared $H_{\rm out}$ programming:** Distinct proofs embed independent $256$-bit tree salts in every committed message $m_\tau$, bounding cross-proof programming collisions by $N_{\mathrm{prog}}^2 / 2^{256}$ and prior $\mathcal A$ hits by $q_H N_{\mathrm{prog}} / 2^{256}$.
- **Adaptive tenant corruption & cross-tenant isolation:** Corrupting a tenant exposes only client-held credentials; prover masks $\omega^\pi_j$ are erased immediately upon release or abort (`R10`). Honest-tenant proofs are never revealed to $\mathcal A$, per-response transcripts carry zero shared batch roots ([Spec 02](02-soundness.md) §4.1), and static weight codewords in [Spec 09](09-model-commitment.md) are opened only inside freshly blinded in-circuit HCO columns, suffering zero cross-proof wear-out.

### 4.5 Concrete Lifetime Advantage Budget

`[Paper]` Evaluate Theorem 4.1 at $|\mathbb E| = p^3 \approx 2^{192}$, $N_\pi \le 2^{48}$ released proofs, $J \le 4$ retries, $q_H \le 2^{80}$, $q_P \le 2^{80}$, $N_{\mathrm{prog}} \le N_\pi J r_{\mathrm{FS}} \le 2^{60}$, $N_{\mathrm{com}} \le 2^{64}$, $q_F \le 2^{72}$ (§5.4), and $N_{\mathrm{req}} \le 2^{48}$:
- **Mask degeneracy:** Per proof $\varepsilon_{\mathrm{deg}} \lesssim \ell n / |\mathbb E| \le 2^{40} / 2^{192} = 2^{-152}$, giving $N_\pi \varepsilon_{\mathrm{deg}} \lesssim 2^{-104}$;
- **$H_{\rm out}$ programming collisions:** $(2^{140} + 2^{120}) / 2^{256} \approx 2^{-116}$;
- **$H_{\rm in}$ sponge hiding:** $2^{80} \cdot 2^{64} / 2^{255} = 2^{-111}$;
- **LogUp pole-retry bias:** $\varepsilon_{\mathrm{pole}} < 2^{-138}$ ([Spec 04](04-completeness.md) Theorem 1, [Spec 05](05-computation-model.md) §1.5), giving $2^{48} \cdot 4 \cdot 2^{-138} = 2^{-88}$;
- **$N_s$ collisions:** $2^{96} / 2^{257} = 2^{-161}$;
- **Keyed-sponge PRF:** $\mathsf{Adv}^{\mathrm{PRF}} \approx 2^{-95}$ (§5.4).

Summing all cryptographic terms yields $\approx 2^{-88} + N_{\mathrm{mid}} \delta_{\mathrm{setup}} + \mathsf{Adv}^{\mathrm{AEAD}} + \delta_{\mathrm{num}} + \delta_{\mathrm{flt}} \ll 2^{-40}$, provided $\delta_{\mathrm{num}} = 0$ and $\delta_{\mathrm{flt}} = 0$.

### 4.6 Protecting the "Provability Bit" ($\delta_{\mathrm{num}} = 0$)

In Hybrid $H_3$, every externally observable non-delivery must be deterministically explainable from $(\mathcal L_i, \mathcal O)$. If honest floating-point execution ever violated block tolerances on certain prompts, proof failure would depend on hidden internal activations that $\mathcal S$ cannot compute, incurring

$$
\delta_{\mathrm{num}} = \sum_{i \le N_\pi} \Pr\bigl[\text{request } i \text{ suffers numerical proof rejection} \;\big|\; \mathcal L_i\bigr].
$$

**Corollary 4.3** `[Paper]`: *Even a $2^{-20}$ per-request numerical rejection rate allows an adaptive adversary issuing $2^{20}$ requests to achieve $\Omega(1)$ distinguishing advantage.*

Furthermore, **secret-triggered numerical failures cannot be masked by declaring a public outage in $\mathcal O$**: if an online request's hidden activation violation triggers an outage entry in $\mathcal O$, the presence of that outage entry is itself a 1-bit function of hidden activations that $\mathcal F_{\mathrm{API}}$ cannot simulate. Public outage declarations in $\mathcal O$ preserve zero knowledge **only** when the decision to declare an outage depends solely on secret-independent infrastructure events or offline kernel testing. Consequently, $\delta_{\mathrm{num}} = 0$ is achieved exclusively through certified-tolerance completeness under `H-contract` ([Spec 04](04-completeness.md) Corollary 3.1, including additive underflow floors in every operator template of [Spec 06](06-tolerance-and-cheats.md) §2.2). Should an online self-check (`R13`) ever detect a kernel contract bug, that single request incurs a bounded $\delta_{\mathrm{num}}$ incident, and the provider immediately rotates `model_id` publicly to retire the faulty kernel configuration.

### 4.7 Streaming Token Timing (`H-hook`)

`[Assume]` **Premise `H-hook`:** *The per-chunk latency increment introduced by FlashProve-Next's online capture hooks is a distribution determined solely by $(\mathcal L_i, \mathrm{Prof}, \text{independent randomness})$.*

Two architectural paths can realize `H-hook`: (i) padding online sponge hashing on GPU to worst-case `Prof` dimensions $V_{\mathrm{tok},\max}$, or (ii) decoupling hashing from the inference critical path via asynchronous device-to-host DMA copy at reserved bandwidth and post-stream commitment construction ([Spec 05](05-computation-model.md) §5.1.2 `D2(b)`). `[Est]` Arithmetic throughput estimates on an `NVIDIA RTX 4070 Ti SUPER 16 GB` (`Qwen3-0.6B`, [Spec 05](05-computation-model.md) §5.2) indicate synchronous on-GPU Poseidon2 hashing consumes $\approx 39\%$ of full-GPU sponge capacity during batch-32 decode and exceeds $100\%$ during prefill, making asynchronous copy (`ii`) the practical path; until end-to-end streaming jitter is benchmarked, Theorem 4.1 claims transcript zero knowledge, with `H-hook` stated explicitly for streaming timestamps.

### 5.3 Dual-Nonce Uniqueness

`[Def]` By [Spec 01](01-relation.md) §5.3, $\mathsf{ctx}_i = \mathsf{Enc}(\texttt{dom}_\xi, v_{\rm rel}, e, \mathsf{dig}(x^{\rm core}_{\mathrm{pub},i}), N_{c,i}, N_{s,i}, \mathsf{sess}, i_{\mathrm{turn}})$ uses injective fixed-width typed encoding, extended by `(d_t, t, bkt/inv, bucket_block)`.

**Lemma 5.1 (Pairwise Distinct PRF Queries)** `[Paper]`: *Outside of $N_s$ collisions (probability $\le N_{\mathrm{req}}^2 / 2^{257}$), every PRF evaluation point across an entire epoch is pairwise distinct regardless of how maliciously clients choose or repeat $N_c$. Consequently, in Hybrid $H_4$, all sampling variates across all requests are jointly independent uniform draws matching $\mathcal F_{\mathrm{API}}$.*

Client nonce $N_c$ prevents provider replay of stale proofs ([Spec 01](01-relation.md) §5.5), while server randomness $N_s$ prevents client chosen-nonce common-random-number probing. Retransmissions carrying an identical API idempotency key return the cached $(y, N_s, \texttt{proof\_id})$ (`R12`), whereas unkeyed resends and retries draw a fresh $N_s$.

### 5.4 Poseidon2 Keyed-Sponge Sampling PRF

Low-degree algebraic PRGs (such as $u_{t,v} = (k_1 + v k_2)^7 + k_3$) are $8$-wise algebraically dependent across vocabulary index $v$ and fail joint pseudorandomness. FlashProve-Next instead instantiates $\mathsf{PRF}_{K_{\rm prf}}$ over the width-12 Goldilocks Poseidon2 permutation $P$ (capacity $c = 4$ elements $= 256$ bits, rate $8$ elements):

`[Def]`
- **Keyed PRF:** $\mathsf{PRF}_K(\mathsf{in}) = \mathrm{Trunc}_8\,P\bigl(K \Vert \mathsf{Enc}(\texttt{dom}_{\rm prf}, \mathsf{in})\bigr)$, placing the $4$-element key $K$ in the capacity lanes and the fixed-width input in the $8$ rate lanes (absorbing multi-block inputs via full-state keyed duplex).
- **Domain separation from $H_{\rm in}$:** Unkeyed $H_{\rm in}$ initializes capacity lanes to a fixed public constant $\texttt{IV}_{\rm in}$ disjoint from key-domain tags while absorbing a distinct domain tag in rate lane $0$.
- **Discrete variate extraction:** Splitting the low $48$ bits of each of the $8$ output elements into two $24$-bit Gumbel table indices yields $16$ bucket variates per permutation call, plus $1$ call for the $48$-bit intra-bucket inverse-CDF variate $U_t$.

`[Paper]` **Ideal-permutation PRF security.** By standard multi-key keyed-sponge / truncated-permutation bounds against adversaries making $q_P$ forward/inverse permutation queries and $q_F$ PRF evaluations across $\mu \le 2^{20}$ epoch-tier keys (Andreeva–Daemen–Mennink–Van Assche, FSE 2015; Mennink–Reyhanitabar–Vizár, ASIACRYPT 2015; Daemen–Mennink–Van Assche, ASIACRYPT 2017),

$$
\mathsf{Adv}^{\mathrm{PRF}} \;\lesssim\; \frac{(q_F + q_P)^2}{2^{256}} + \frac{\mu\,q_P}{2^{256}}.
$$

Bucketed sampling ($\beta_s = 32, V_{\max} = 2^{18}$) invokes $\lceil B / 16 \rceil + 1 \le 513$ permutations per generated token; across $N_{\mathrm{req}} \le 2^{48}$ requests averaging $\le 2^{14}$ generated tokens, $q_F \le 2^{72}$ (or $\le 2^{75}$ at worst-case $T_{\mathrm{pad}} \le 2^{17}$). With $q_P \le 2^{80}$, $\mathsf{Adv}^{\mathrm{PRF}} \approx 2^{-95}$. `[Assume]` Poseidon2 with audited Plonky3 round constants behaves as an ideal permutation.

`[Est]` **In-circuit efficiency.** For a vocabulary of size $V = 151{,}936$ (`Qwen3`) at $\beta_s = 32$, each checked generation step requires $\lceil 4748 / 16 \rceil + 1 = 298$ Poseidon2 permutations ($\approx 3.5 \times 10^4$ S-boxes). Across $k_2 = 105$ sampled steps, total PRF work per proof is $\approx 3.7 \times 10^6 \approx 2^{21.8}$ S-boxes—a $56\times$ reduction compared to per-token vocabulary PRF evaluation ($\approx 2^{27.6}$ S-boxes)—while preserving deterministic step-wise noise for coupled speculative decoding (`[Lean: Speculative.specLoop_eq_seqGen]`).
