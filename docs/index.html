How FlashProve-Next Differs from FlashProve 与 FlashProve 的设计对比

Anthropic's FlashProve demonstrated that zero-knowledge proofs can verify a closed-weight 400B MoE model without hardware enclaves. FlashProve proves exact full-layer execution of an integer surrogate, while FlashProve-Next makes different trade-offs targeted at native floating-point API serving. Anthropic 的 FlashProve 证明了不靠硬件飞地（TEE）也能验证 400B 闭源模型。FlashProve 证明确定性整数替身模型的逐层精确执行，而 FlashProve-Next 面向原生浮点在线服务做出了不同的设计取舍。

What a Verified Proof Guarantees: The provider holds a computation trace consistent with the real model configuration committed in model_id, that trace produced this visible reply for this request under the committed sampling rule (including hidden prompts and hidden chain of thought), and both the cost share of out-of-tolerance computation and the share of rule-violating tokens lie below public thresholds. 验证通过代表什么：服务商确实持有一条与 model_id 承诺的线上模型配置一致的计算轨迹；这条轨迹按规定的采样规则针对本次请求生成了用户看到的回复（包含其中隐藏的系统提示词与隐藏思维链）；且轨迹中超出硬件浮点误差范围的计算量占比、违反采样规则的 token 占比都低于公开阈值。

How It Works in Three Steps 三步完成出证与验证

Online serving adds read-only boundary recording; proof generation runs asynchronously after the reply finishes streaming. 在线服务挂接只读记录钩子；零知识证明在回复流式结束后于后台异步完成。

Folded Zero-Phase-2 Backend (8 MiB)零 Phase-2 折叠后端（定长 8 MiB）

Batched folded ZK-Basefold + FracLogUp-GKR eliminates the Phase-2 circuit blow-up, compressing unsliced Qwen3-0.6B (ExtSeed-153, Q=128, 1.47B cells) and 36-layer Qwen3-4B into an exact 8 MiB container with ~10 ms Rust / 10.8 s Python verification. 批量折叠 ZK-Basefold 与 FracLogUp-GKR 彻底消除了 Phase-2 膨胀，将完整 Qwen3-0.6B（ExtSeed-153, Q=128, 14.7 亿格）与 36 层 Qwen3-4B 压进精确 8 MiB 容器，支持 Rust 约 10 ms 与 Python 10.8 s 验证。

Local Rounding-Contract Checks按硬件算子规则核验浮点误差

Each sampled block checks the engine's output against its own committed input using the operator's declared rounding bound, preventing cross-layer error blow-up while keeping R32 numerics overhead around 1.2%–2.7% on vLLM. 在每个被抽查算子块上从引擎记录的真实输入出发传播单步舍入上限，误差不跨层爆炸；开启满足合约的 R32 浮点配置仅耗 1.2%–2.7% vLLM 吞吐。

Private API & Schema Semantics完整商业 API 与结构化约束

Supports hidden system prompts, hidden <think> CoT, multi-turn AEAD state chains, tool witnesses, and minimal byte-DFA JSON Schema masks bound over 𝔽p3 in O(k_2 Q_pad) cells. 原生支持隐藏系统提示词、隐藏 <think> 思维链、跨轮加密状态链、工具调用见证，以及在 O(k_2 Q_pad) 格内绑定的最小字节自动机 JSON Schema 约束解码。
